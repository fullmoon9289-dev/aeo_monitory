7. 골드만 검색어 CSV를 운영 사이트에 저장했습니다. 저장된 행 수, 기간, 클릭·노출 합계를 원본과 대조했고, 위드유의 기존 저장 상태가 바뀌지 않았는지 확인했습니다.
8. 상세 검색 성과 보고서를 로컬에 작성하고 사이트의 저장된 검색 분석 화면을 확인했습니다.
9. 사용자에게 두 병원의 실제 데이터 확보 수준이 다르며, 두 곳 모두 실제 AI 언급·인용률은 아직 측정하지 않았음을 정정·설명했습니다.

## 이번 UI 통합

- `components/workspace-shell.tsx`를 공통 틀로 사용합니다. 위드유의 왼쪽 메뉴, 상단 바, 배경과 본문 폭을 두 병원에 적용했습니다.
- 골드만의 가로 메뉴·큰 소개 영역을 카드 중심 대시보드로 바꿨습니다. 실제 구현된 기능에 맞는 메뉴를 유지하며 위드유의 예시 데이터를 복제하지 않았습니다.
- 골드만 첫 화면은 운영 데이터베이스의 최신 CSV를 읽어 클릭·노출·클릭률과 클릭이 많은 검색어 또는 페이지를 보여줍니다. 가져온 행의 합계라는 범위를 표시합니다.
- 기존 고정 문구 'CSV 대기'를 없애고 불러오는 중·자료 없음·저장됨·오류 상태를 실제 조회 결과로 표시합니다. CSV 저장 성공도 대시보드에 전달합니다.
- AI 답변 인용률은 '미측정'으로 표시합니다. 날짜별 추이가 없는 파일에 가상의 전후 추이 그래프를 만들지 않았습니다.
- 골드만 병원 지식 베이스는 기존 표본 진단에 사용한 공개 출처를 보여주고, 연동 및 설정에는 실제 연결 범위를 표시합니다.
- 모바일에서는 메뉴 버튼으로 같은 병원 메뉴를 엽니다. 숨겨진 메뉴가 탭 이동 대상이 되지 않도록 처리했습니다.
- CSV 입력란을 병원별로 다시 생성해 파일·확인 상태가 섞이지 않도록 했고, 날짜 입력의 라벨을 명시적으로 연결했습니다.
- 병원별 원본 데이터 파일, 운영 데이터베이스 구조와 API 저장 규칙은 변경하지 않았습니다.

## 병원별 데이터와 진단 상태

| 구분 | 위드유 | 골드만 |
|---|---|---|
| 공식 홈페이지 정보 | 기존 공개 정보 정리 자료 | 홈페이지 표본 관찰 자료 |
| 관찰 시점 | 홈페이지 자료 9/9, 공개 검색 표본 9/10 | 홈페이지 표본 9/11 |
| 공개 검색 | 질문 5개의 공개 검색 결과군 관찰 | 제공된 서치콘솔 자료 분석 |
| 서치콘솔 CSV | 저장된 자료 없음 | 검색어 자료 저장 완료 |
| 성과 대시보드 | `performanceDemo`의 예시 데이터 | CSV에 포함된 검색어 행의 실제 합계 |
| 실제 AI 언급·인용·추천 방문 | 미측정 | 미측정 |
| 전체 사이트 검사·계정 URL 검사 | 완료하지 않음 | 완료하지 않음 |

**위드유의 '자료 보존'은 기존 공개 정보와 화면의 보존입니다. 실제 검색 성과 데이터를 확보했다는 뜻이 아닙니다.** 위드유 AI 성과 화면의 언급률·인용률·유입·전후 개선 수치는 실측값으로 보고하거나 고객 성과로 홍보하면 안 됩니다.

골드만 검색 통계는 사용자 제공 자료의 범위에서 합계를 검증했습니다. 이를 전체 홈페이지 진단 완료, AI 추천 성과 검증 또는 개선 효과의 인과 증명으로 확대해 설명하지 않습니다.

## 골드만 분석 방법과 해석

- 조회 기간은 원본 날짜별 자료의 최소·최대 날짜로 확인했습니다. 내보내기 날짜와 조회 종료일은 서로 다릅니다.
- 전체 클릭·노출은 날짜별 자료를 합산했고 기기별·국가별 합계와 일치하는지 대조했습니다.
- 클릭률은 클릭÷노출로 계산했습니다. 평균 순위는 원본에 반올림된 날짜별 순위를 노출수로 가중한 추정값으로 표시했습니다.
- 최근 28일과 직전 28일을 비교했습니다. 기간 길이와 요일 구성은 같지만 계절·수요·검색어 구성 변화의 영향을 통제한 실험은 아닙니다.
- 검색어와 페이지 자료는 별개의 집계입니다. 별도 교차 자료 없이 특정 검색어의 클릭을 특정 페이지의 실적으로 연결하지 않았습니다.
- 검색어 목록은 전체 검색 실적을 모두 포함하지 않습니다. 익명 처리, 목록 범위, 페이지·속성 집계 차이 때문에 표별 합계가 달라질 수 있습니다. 서로 다른 표의 수치를 더하지 않습니다.
- 모바일 기기 이용자의 실적과 `m.` 주소의 실적은 다른 기준입니다. 모바일 주소에 클릭이 적다는 사실만으로 모바일 방문이 없거나 설정 오류라고 단정하지 않습니다.
- 콘텐츠 우선 검토 주제는 포경수술, 콘딜로마, 정관수술입니다. 비용·회복과 같은 구체적인 질문에서 발생한 클릭을 콘텐츠 보완의 단서로 활용했습니다. 임의의 업계 평균 클릭률이나 AEO 점수를 만들지 않았습니다.
- 임상 내용과 비용·치료 효과 문구는 실제 병원 자료와 담당 의료진 검토가 필요합니다. 제안 내용이 원래 병원 홈페이지에 반영됐다는 뜻은 아닙니다.

집계 참고: [Google Search Console 실적 보고서](https://support.google.com/webmasters/answer/7576553?hl=ko), [Google 모바일 사이트 안내](https://developers.google.com/search/docs/crawling-indexing/mobile/mobile-sites-mobile-first-indexing).

## 구현의 현재 범위

- 병원 식별자: `withyou-clinic`, `goldman-clinic`.
- 선택 상태는 병원 드롭다운, URL의 `clinic` 값, 브라우저 선택 설정으로 유지합니다. 검색 실적 자체를 브라우저 설정에만 저장하지 않습니다.
- `GET /api/search-console-imports?clinicId=...`는 해당 병원의 가장 최근 자료 한 개를 반환합니다.
- `POST /api/search-console-imports`는 병원별 자료를 새 기록으로 추가합니다. 기존 기록을 일괄 덮어쓰지 않습니다.
- 검색어 또는 페이지 CSV를 하나씩 가져올 수 있습니다. 현재 UI는 가장 최근 저장 파일 한 개를 보여주며 ZIP의 모든 표를 통합하는 대시보드는 아닙니다.
- 파일 크기·행 수·필수 열·숫자·기간·병원 식별자를 확인합니다. 페이지 CSV는 도메인도 검사합니다. 검색어 CSV에는 원본 속성 인증 정보가 없으므로 파일 출처를 사용자가 확인해야 합니다.
- CSV를 가져오면 파일에 있는 행의 지표와 목록을 계산합니다. 홈페이지 표본 진단 보고서가 자동으로 다시 작성되거나 실제 AI 답변 모니터가 연결되는 것은 아닙니다.
- 발행 일정과 대기열을 저장하는 기능은 외부 서비스에 글을 실제 게시하는 기능과 구분합니다.

- 상세 원본과 실제 수치 보고서는 공개 Git 문서에 포함하지 않습니다. 로컬 프로젝트의 Git 제외 경로 `work/session-archives/2026-09-11/`에 백업 묶음과 내용 목록을 보관합니다.
- 로컬 백업에는 원본 ZIP, 추출한 분석용 CSV, 계산 결과, 상세 보고서, 저장 확인 기록, 공개 홈페이지 관찰 자료를 포함합니다. SHA-256 목록으로 복사본의 무결성을 확인합니다.
- 로컬 묶음은 작업 자료의 백업입니다. 운영 데이터베이스 전체의 복구용 덤프는 아닙니다. 원본 CSV와 분석에 사용한 자료를 통해 이번 분석을 다시 확인할 수 있습니다.
- Git push는 소스·문서 저장입니다. 운영 데이터베이스 자료 변경과 운영 사이트 재배포는 별도 작업입니다. 이번 작업은 기록 저장과 UI 통합을 함께 수행합니다. 소스와 문서는 GitHub에 저장하고, 검증한 UI는 기존 운영 사이트에 반영합니다.

5. 실제 AI 추천 방문 및 예약 효과는 방문 분석과 전환 자료를 확보한 뒤 평가합니다. 예시 화면의 값을 실측값으로 전환했다고 설명하지 않습니다.
6. 전체 실적·검색어·페이지·기기·추세를 사이트에서 함께 보여주는 통합 가져오기와 보고서 갱신은 아직 구현되지 않은 후속 기능입니다.
7. 홈페이지 개선은 먼저 수정 대상과 날짜를 기록하고, 이후 같은 길이의 기간으로 변화를 관찰합니다. 실제 수치 없이 효과를 보장하지 않습니다.

## 운영 원칙

- 고객에게는 실제 측정, 공개 표본 관찰, 해석·제안, 예시 화면을 구분해 설명합니다.
- 원본 CSV·ZIP, 개인 계정 정보, 인증 토큰과 DNS 확인 값은 공개 Git 저장소에 올리지 않습니다.
- 위드유를 골드만으로 덮어쓰지 않습니다. 병원 추가·가져오기·일정 변경 시 병원 식별자를 확인합니다.
- 저장·배포 성공은 실제 결과를 다시 확인한 뒤 알립니다. 확인하지 않은 계정 연결, AI 측정, 게시 완료를 완료로 표시하지 않습니다.
